## 1. 总体定位

本平台为**教育 AI 平台**，两大核心模块互为支撑：

| 模块 | 定位 | 一句话概括 |
|------|------|-----------|
| 知识图谱 | 核心数据支撑模块 | 一套**"活文档"**：既能支撑教学引导，又随答疑数据反哺而成长 |
| AI 答疑 | 核心教学交互模块 | 以**启发式教学**为主（拒绝直接投喂答案），通过对话与智能分析实现"教学相长" |

**核心设计原则**（源自两篇文档的共同主张）：

1. **启发式 > 直接给答案**：答疑的目标是教会学生思考，不是替学生做题。
2. **数据闭环 > 一次性交付**：图谱与答疑都不是静态系统，掌握信号 → 图谱点亮 → 修正先验 → 反哺教学。
3. **成本可控 > 极致效果**：通过小模型部署、按需调用等手段控制单次答疑成本，支撑更大并发与长期运营。
4. **业务隔离 > 单库耦合**〔推演〕：权威图谱（教育局数据）保持只读权威；答疑产生的派生知识（题型、别名、掌握度）独立沉淀，避免污染权威数据。

## 2. 用户角色与核心场景

### 2.1 角色定义〔推演〕

| 角色 | 说明 | 核心诉求 |
|------|------|---------|
| 学生（S） | 答疑主用户 | 不会做 → 有人引导我思考；练会 → 看得见自己掌握在哪 |
| 家长（P） | 报表查看者 | 孩子哪儿薄弱、最近学得怎么样 |
| 教师（T） | 教学管理者 | 全班掌握分布、给哪些学生布置同类练习 |
| 教研 / 运营（A） | 内容与数据维护者 | 图谱对不对、新题型有没有挂到正确知识点 |

### 2.2 核心场景清单〔推演〕

| 编号 | 角色 | 场景 | 期望结果 |
|------|------|------|---------|
| SC-01 | 学生 | 遇到不会做的题（文字/拍照）向 AI 答疑求助 | AI 引导式提问，逐步想通，不直接给答案 |
| SC-02 | 学生 | 答疑后 AI 推荐同类题巩固 | 举一反三，真正掌握而非"听懂了" |
| SC-03 | 学生 | 查看自己的知识图谱 | 知识点按掌握度点亮，知道薄弱点在哪 |
| SC-04 | 学生 | 图谱上看到"疑似待确认"的节点 | 明白这是推断、需要确认，而非真的掌握/薄弱 |
| SC-05 | 家长 | 查看孩子掌握度报表 | 快速定位薄弱科目与知识点 |
| SC-06 | 教师 | 查看班级知识点掌握分布 | 针对性布置练习 |
| SC-07 | 教研 | 处理新题型归属 | 高效确认题型 → 知识点映射，回流解析先验 |
| SC-08 | 教研 | 考纲变化后更新图谱 | 权威数据同步 + 派生层联动迁移 |

## 3. 知识图谱模块

### 3.1 业务目标

- **核心目标**：为平台提供**核心数据支撑**，让"知识"可被结构化地组织、检索与学习。
- **定位**：一份**"活文档"**——不是静态存储，而是随教学数据持续更新、自我完善的图谱。
- **作用**：
  1. 支撑**引导式教学**：通过知识点路径，引导学生发现问题、自主思考（教学相长）。
  2. 联动**家长端报表**：学生掌握情况可视化，家长可查看知识薄弱点。
  3. 保持**扩展性**：可对接不同的教材、学段、考纲。

### 3.2 "活文档"的三层含义〔推演〕

| 层面 | 含义 | 体现 |
|------|------|------|
| **可成长** | 图谱能吸纳新知识，不被初始导入冻结 | 答疑沉淀题型 → 题型库聚合 → 补全图谱外的"别名/题型"关系 |
| **可校验** | 图谱内容是经过确认的，而非放任自流 | 派生观测有置信度与状态（确定/疑似），低置信挂起人工确认 |
| **可追溯** | 每个变更都能溯源，错了能修正 | 观测记录来源、保留首次时间，重判打标、不静默删除 |

### 3.3 方案设计要点（原始文档）

| 环节 | 方案 |
|------|------|
| 数据获取 | 采用**开源数据**（参考 KnowEdu、EduKG、好未来小学知识图谱等） |
| 文档处理 | 按**学段切片**（如小学/初中/高中）组织知识点 |
| 提问处理逻辑 | **引导式提问**：不直接给答案，通过提问引导学生思考 |
| 存储部署 | **轻量存储**，避免重依赖，便于快速迭代 |
| 与 AI 助手联动 | 图谱为 AI 答疑提供上下文，答疑结果反哺图谱 |

### 3.4 数据模型设想〔推演〕

> 以下为基于文档目标 + 当前技术实现（Neo4j 权威图 + kg-sync 镜像 + MySQL 派生层）的模型推演。

**权威图谱（只读，教育局数据源）**

| 对象 | 说明 |
|------|------|
| 知识点节点 | key=TextbookKP URI、label、难度、重要性、认知层级、状态 |
| 关系边 | 包含 / 属于单元 / 匹配权威知识点 / 相关 / 发展 等 |
| 学段切片 | 按学段（小学/初中/高中）组织，URI 内嵌年级信息 |

**派生层（可成长，MySQL 独立存储，业务隔离）**

| 对象 | 说明 |
|------|------|
| 个体派生观测 | 某学生 × 某题型 × 某知识点，去重计数、置信、状态（NEW/RESOLVED/CONFLICTED/READJUDICATED/HUMAN_REVIEW） |
| 题型库 | 沉淀"知识点的题型"，含年级分布桶（假设法/二元一次方程组 各自命中人数与占比），CANDIDATE → STABLE |
| 掌握度 | 学生 × 知识点，单源存储，含解析状态与置信（确定/疑似） |

**分层关系示意**：

```
  权威图谱（Neo4j，只读）
    ▲ 只借用 kp_uri 结构
  派生层（MySQL：观测 / 题型库 / 掌握度）
    ▲ 解析管线命中后点亮
  学生端图谱渲染（前端叠加掌握度）
```

### 3.6 关键业务流程〔推演〕

**流程 1：题型解析与点亮**

```
AI 答疑产出题型label/掌握信号
        │
        ▼
① 权威镜像精确/LIKE 命中 ──命中──▶ RESOLVED，点亮
        │未命中
        ▼
② 题型库年级匹配（学生年级锚）──命中──▶ RESOLVED，点亮
        │未命中
        ▼
③ LLM 消歧（label + 候选kp）──高置信──▶ RESOLVED，点亮
        │低置信
        ▼
④ PENDING 挂起（不点亮、不落掌握度，前端渲染"疑似待确认"）
```

**流程 2：维护闭环**

```
周期扫描 → 发现冲突信号（诊断冲突/掌握度矛盾/分布异常/低置信）
        │
        ▼
重判（年级锚 + 题型库先验 + LLM）
        │
   ┌────┴────┐
  高置信    低置信/仍歧义
   │          │
   ▼          ▼
自动修正     HUMAN_REVIEW
（观测+题型库统计+先验漂移）  → 人工确认 → 回流
```

### 3.7 竞品参考与差异化

参考方向：
- **大型平台**：知识体系完整但封闭、更新慢、不面向单校/个人。
- **小型工具**：轻量但知识覆盖不足、无教学引导能力。
- **通用工具**：覆盖面广但无教育语义、无法支撑"教与学"闭环。

**差异化**：以"**活文档 + 引导式教学 + 与答疑联动**"为核心，避免静态图谱 / 无教学语义的通用方案。

### 3.8 主要问题深化（原文档核心问题）

> **问题 ① 数据来源与清洗**
> 各个知识图谱的数据来源从哪里来？如何清洗成可用、可靠的知识点数据？

- 现状〔推演〕：以教育局开源/下发的知识点数据为权威源，需质检关键字段（难度、重要性、认知层级、状态、合并去向）。
- 影响：数据质量直接决定解析准确率与图谱可信度。
- 解决方向〔推演〕：权威源只读 + 质检流程 + 派生层补足图谱外的题型/别名。
- 风险：开源数据覆盖不全、命名不规范 → 需要清洗规则与人工校验兜底。

> **问题 ② 不同教材与知识点关联管理**
> 不同教材对同一知识点可能使用不同名称 / 不同组织方式，如何管理与教材的关系？

- 现状〔推演〕：知识点 key=TextbookKP URI（教材内嵌），天然支持跨教材；但同一题型在不同教材/年级的归属不同（鸡兔同笼 → 假设法 / 二元一次方程组）。
- 影响：关联管理不当会导致解析歧义、点亮错位。
- 解决方向〔推演〕：题型库按年级拆分分布桶，以学生年级做"强先验非硬规则"锚定；跨年级薄弱是特性而非缺陷。
- 风险：冷启动时年级桶无数据 → 需要 LLM 消歧与人工确认补充。

> **问题 ③ 教育局修改考点如何更新图谱**
> 考点会随教育局政策 / 考纲变化而调整，知识图谱如何保持同步更新？

- 现状〔推演〕：权威镜像同步 + 合并标记（mergedToUri）覆盖部分迁移场景。
- 影响：不同步会导致解析到已废弃/被合并的知识点。
- 解决方向〔推演〕：镜像同步策略 + 派生层联动迁移（观测/题型库指向旧 URI 的迁移处理）。
- 风险：考纲变更触发面大，迁移规则需人工确认。

## 4. AI 答疑模块

### 4.1 业务目标

- **核心目标**：以**启发式教学**为核心，**拒绝直接投喂答案**，通过引导实现"教学相长"。
- **成本**：控制 AI 调用成本，支持**小模型部署**，降低单次答疑成本。
- **用户**：面向学生（答疑主场景），联动家长（报表查看）与教师。
- **迭代目标**：持续沉淀答疑数据，优化教学引导效果与智能分析能力。

### 4.2 启发式教学的设计原则〔推演〕

| 原则 | 说明 | 反面 |
|------|------|------|
| 不投喂答案 | 先引导拆题、定位卡点 | 直接给完整解法 |
| 因卡施教 | 根据学生卡在哪一步给不同提示 | 千篇一律的讲解 |
| 举一反三 | 讲一题 → 同类题巩固，验证真掌握 | 讲完即走 |
| 留有余地 | 提示到"差一步"为止，让学生自己迈出最后一步 | 全流程代劳 |

### 4.3 关联模块

| 关联模块 | 说明 |
|---------|------|
| **知识图谱** | **双向联动**：图谱提供知识点上下文；答疑产生的掌握信号反哺图谱点亮 |
| **家长端报表** | 答疑与掌握度数据 → 家长可视化报表 |
| **小模型部署** | 核心答疑能力可下沉到小模型，控制成本、支持更大并发 |

### 4.4 核心交互流程〔推演〕

**主流程：引导式答疑**

```
学生提问（文字/拍照）
     │
     ▼
① 诊断 decide：识别题型、定位知识点、判断卡点/掌握程度
     │
     ▼
② 引导 generate：给出"差一步"的引导话术，不直接给答案
     │
     ▼
③ 学生作答 ◀── 循环：答错 → 细化提示；答对 → 肯定并确认思路
     │
     ▼
④ 举一反三：推荐同类题，验证是否真正掌握
     │
     ▼
⑤ 掌握信号落库（题型 label / 掌握度 / 诊断结果 → 图谱与报表）
```

**核心诉求"拒绝投喂答案"的落地**：diagnose 阶段先判断学生卡点与能力，generate 阶段只给**最少的必要提示**，让学生完成最后一步推理。

### 4.5 方案设计要点（原始文档）

**核心理念参考**（各取所长）：

| 参考对象 | 借鉴点 |
|---------|--------|
| 可汗学院 | 启发式教学、视频 + 练习的知识路径 |
| 科大讯飞 | AI 交互体验、语音/对话式答疑 |
| 猿辅导 | **举一反三**：讲一题 → 练同类题，强化掌握 |
| 好未来 | **教学闭环**：讲解 → 练习 → 反馈 → 掌握度管理 |

**关键设计**：

1. **对话存储**：对话记录存入 **MongoDB**（支撑高频写入与查询）。
2. **AI 答疑交互设计**：引导式提问 → 学生作答 → AI 反馈 → 同类巩固（举一反三）。
3. **AI 智能分析设计**：从对话与作答中分析学生掌握度、薄弱点，输出教学建议。

### 4.6 智能分析设计〔推演〕

| 分析项 | 输入 | 输出 |
|--------|------|------|
| 掌握度评估 | 答疑诊断 + 举一反三结果 | 学生 × 知识点 掌握度（确定/疑似） |
| 薄弱点诊断 | 多轮答疑记录 | 薄弱知识点列表 + 可能根因 |
| 教学建议 | 掌握度分布 | 下一步学习路径 / 同类练习推荐 |
| 家长报表 | 掌握度 + 答疑摘要 | 面向家长的可视化报告 |

### 4.7 方案选型对比

**对话存储选型**：

| 维度 | MongoDB | Elasticsearch | HDFS |
|------|---------|---------------|------|
| 适用场景 | 高频对话读写 | 全文检索 / 日志分析 | 海量离线分析 |
| 读写性能 | 高（文档型） | 中（索引开销） | 低（批处理） |
| 实时性 | 高 | 中 | 低 |
| 复杂度 | 低 | 中 | 高 |
| 选型结论 | ✅ 采用 | — | — |

**智能分析 vs 传统 BI**：

| 维度 | AI 智能分析 | 传统 BI 报表 |
|------|------------|-------------|
| 分析方式 | 自动洞察、自然语言理解 | 人工配置看板、固定指标 |
| 产出 | 教学建议 / 薄弱点诊断 | 统计图表 |
| 门槛 | 依赖 AI 能力 | 依赖配置 |

### 4.8 竞品分析与规避

| 竞品 | 特点 | 我们的规避/差异点 |
|------|------|------------------|
| 好未来 | 教学闭环成熟 | 拒绝"标准答案投喂"，强调引导 |
| 科大讯飞 | AI 语音/交互强 | 聚焦学科深度答疑而非泛对话 |
| 猿辅导 | 举一反三训练 | 以掌握度驱动同类练习，而非题海 |
| 国家教育平台 | 覆盖面广、权威 | 轻量、可扩展、面向单校落地 |

### 4.9 主要问题深化

> **问题 ④ 缺少 OCR 整体的业务流程**
> 原文档末尾注明：**"缺少 OCR 整体的业务流程"**——即拍照/图片题目如何被识别、如何进入答疑流程，尚未定义完整的业务链路。

- 影响〔推演〕：学生真实使用中"拍照问"是高频入口，缺流程则主场景断裂。
- 解决方向〔推演〕：拍照 → 题目识别 → 文本化 → 进入诊断/引导流程；需明确识别质量校验与"识别不准"兜底。
- 风险：识别准确率直接影响答疑体验，需设计低质量识别的降级策略。

## 5. 两模块联动

### 5.1 联动示意

```
┌─────────────────────┐        引导提问 / 知识点上下文        ┌──────────────────────┐
│     AI 答疑模块      │ ──────────────────────────────────▶ │    知识图谱模块       │
│  对话 · 引导 · 分析  │                                     │  知识点 · 关系 · 学段  │
└─────────────────────┘ ◀────────────────────────────────── └──────────────────────┘
         │            掌握信号 / 薄弱点 / 点亮反馈                     ▲
         │                                                          │
         ▼                                                          │
   ┌─────────────┐           家长端报表 / 教学建议                     │
   │ 掌握度数据   │ ─────────────────────────────────────────────────┘
   └─────────────┘
```

- **正向**：AI 答疑根据图谱定位知识点、组织引导路径。
- **反向**：答疑产生的掌握信号、薄弱点、答错诊断 → 反馈给图谱（点亮 / 修正）。
- **对外**：掌握度与诊断结果 → 家长端报表、教师教学建议。

### 5.2 关键联动链路〔推演〕

| 链路 | 触发 | 流向 | 产出 |
|------|------|------|------|
| 正向定位 | 学生提问 | 题型 label → 知识点 URI | 答疑上下文、引导路径 |
| 反向点亮 | 答疑完成 | 掌握度 → 图谱节点 | 学生端图谱点亮 |
| 反向修正 | 维护周期 / 冲突 | 观测重判 → 题型库 | 先验漂移、可疑修正 |
| 对外报表 | 定时/查询 | 掌握度 → 家长端 | 可视化报表 |

## 6. 主要问题汇总与优先级

| # | 问题 | 模块 | 描述 | 影响面〔推演〕 | 优先级〔推演〕 | 解决方向 |
|---|------|------|------|--------------|--------------|---------|
| P1 | 数据来源与清洗 | 知识图谱 | 开源数据来源、清洗为可靠知识点 | 全图谱可信度 | 高 | 权威源只读 + 质检 + 派生层补充 |
| P2 | 不同教材与知识点关联 | 知识图谱 | 教材各异，同一知识点命名/组织不同 | 解析准确率 | 高 | 题型库年级分布 + 别名管理 |
| P3 | 教育局修改考点的更新 | 知识图谱 | 考纲变化时图谱如何同步 | 解析是否过期 | 中 | 镜像同步 + 合并迁移 |
| P4 | OCR 业务流程缺失 | AI 答疑 | 拍照/图片题目识别与答疑链路未定义 | 主使用场景断裂 | 高 | 补充完整链路（见 §4.9） |
| P5 | 引导式教学落地 | AI 答疑 | 如何"拒绝投喂答案"且不过度打断 | 核心体验 | 高 | 诊断先行 + 最小必要提示 |
| P6 | 掌握度与图谱打通 | 联动 | 答疑掌握信号如何点亮图谱节点 | 产品闭环 | 高 | 解析管线 + 掌握度增强 + 点亮 |
| P7 | 跨年级知识点归属 | 联动 | 同一题型在不同年级归属不同知识点 | 解析准确率 | 高 | 年级锚 + 分布桶 |

> P1–P3 为知识图谱原文档核心问题；P4 为 AI 答疑原文档自述缺失；P5–P7 为两文档联动后归纳。

## 7. 成功指标与验收〔推演〕

### 7.1 产品指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 答疑会话完成率 | 一次提问 → 走完引导 → 举一反三完成的比例 | ≥ 60%〔推演〕 |
| 引导式回答率 | 未直接给答案的比例（抽样评估） | 高（核心体验红线） |
| 掌握度覆盖 | 有掌握度记录的活跃学生比例 | 稳步提升 |
| 图谱点亮可用率 | 解析成功率（非挂起比例） | 逐步提升 |

### 7.2 技术指标

| 指标 | 定义 | 说明 |
|------|------|------|
| 单次答疑成本 | 单会话 LLM token 成本 | 小模型部署 / 按需调用控制 |
| 端到端时延 | 提问 → 收到引导 | 流式输出，可感知延迟低 |
| 解析准确率 | 题型 → 知识点命中正确率 | 镜像命中 / 消歧准确率 |
| 挂起率 | 解析进入 PENDING 的比例 | 反映冷启动阶段需人工确认的负担 |

### 7.3 验收要点〔推演〕

- [ ] 学生端图谱能按掌握度点亮（绿/黄/红），疑似节点以虚线 + "待确认"角标渲染。
- [ ] 解析失败不报错，返回"疑似待确认"，不落掌握度。
- [ ] 派生层任何操作不写入权威图谱（Neo4j / 镜像零写入）。
- [ ] 维护闭环能自动修正高置信冲突，低置信转人工。
- [ ] 家长/教师报表能消费掌握度数据。
